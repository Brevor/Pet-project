# Прототип A1 — «Управление расписанием и залами»

Кликабельный прототип рабочего места администратора студии танцев, закрывающий требование
**A1** из [Requirements](https://github.com/Brevor/Pet-project/wiki/Requirements):

> **A1** · Must · Управление расписанием и залами: создание групповых и индивидуальных занятий,
> назначение преподавателей, учёт занятости залов, поддержка повторяющихся событий.

## Запуск

```
prototype/index.html  —  открыть двойным кликом в Chrome / Edge / Safari
```

Без сборки, зависимостей и сервера. Данные лежат в `localStorage` браузера
(ключ `studiocrm.a1.v1`). Чтобы вернуть демо-данные:

```js
localStorage.removeItem('studiocrm.a1.v1'); location.reload();
```

## Покрытие требования

| Часть A1 | Как реализовано в прототипе |
|---|---|
| Создание групповых занятий | «+ Новое занятие» → тип «Групповое» → выбор группы; либо клик по пустому месту в календаре (время и день подставляются) |
| Создание индивидуальных занятий | Тип «Индивидуальное» + имя ученика; в календаре помечаются бейджем «инд» |
| Назначение преподавателей | Селект преподавателя с автоподстановкой по группе; проверка двойной занятости преподавателя в одно и то же время |
| Учёт занятости залов | Блокировка пересечений по залу при сохранении; вкладка «Залы» — часы и процент загрузки за неделю, число занятий, занятость зала удалить нельзя |
| Поддержка повторяющихся событий | «Еженедельно» + день недели + необязательное «Повторять до»; разовые занятия — по конкретной дате; удаление серии целиком |

Дополнительно: недельный календарь с раскладкой параллельных занятий, фильтры по
преподавателю/залу/типу, метрики недели, проверка вместимости зала (предупреждение, не блокировка),
легенда цветов преподавателей, линия текущего времени.

## Сценарий проверки (5 минут)

1. Открыть календарь — на текущей неделе 16 занятий, часть в двух залах одновременно.
2. «+ Новое занятие» → Групповое → «Hip-Hop · начинающие» → Зал А → понедельник, 18:00, 90 мин →
   **Сохранить**. Появятся два блокирующих сообщения: зал занят и преподаватель занят.
3. Поменять зал на «Зал Б», а преподавателя на «Мария Соколова» → сохранение пройдёт;
   в календаре видно занятие рядом с чужим (раскладка в две дорожки).
4. Выбрать «Открытый класс» (22 ученика) и «Зал Б» (14 мест) — появится жёлтое предупреждение
   о вместимости, но сохранение разрешено.
5. Тип «Индивидуальное» + имя ученика + «Разовое» + другая дата — занятие появится только в эту дату.
6. Вкладка «Залы» — загрузка в часах и процентах, добавить новый зал, попробовать удалить занятый.
7. Перезагрузить страницу — все изменения сохранились.

## Модель данных

```js
rooms:    { id, name, capacity, note }
teachers: { id, name, spec, color }
groups:   { id, name, teacherId, students }
classes:  { id, kind: 'group'|'individual', groupId?, student?, teacherId, roomId,
            repeat: 'weekly'|'once', weekday?, date?, start /*минуты от 00:00*/, duration, until? }
```

Вхождения серии не материализуются в БД: они вычисляются на лету для отображаемой недели,
а конфликты проверяются по всем вхождениям в горизонте года.

## Допущения

Требование A1 сформулировано одной строкой, поэтому детали зафиксированы так:

- рабочий день студии 09:00–22:00, шаг сетки — 15 минут, длительности 45–120 минут;
- занятие принадлежит одной группе; индивидуальное — одному ученику (пары вводятся текстом:
  «Свадебный танец · Орловы»);
- пересечение по залу или преподавателю **блокирует** сохранение, переполнение вместимости —
  только предупреждение;
- серия — «каждую неделю в один и тот же день», с необязательной датой окончания;
- один филиал, один часовой пояс, без праздников и переносов.

## Ограничения прототипа

- только фронтенд на `localStorage`, нет сервера, авторизации и ролей (это A5, A6);
- нельзя отменить или перенести одно занятие внутри серии — только всю серию;
- нет CRUD групп, преподавателей и учеников — они заведены демо-данными;
- нет проверки на сервере: конфликты считаются в браузере.

## Следующие шаги

1. Исключения из серии, перенос и отмена одного занятия, уведомление ученикам.
2. CRUD групп/преподавателей/учеников и запись учеников в группы.
3. Бэкенд (API + БД), серверная валидация конфликтов, оптимистичные блокировки.
4. Роли (A5), стыковка с абонементами (A3) и отметкой посещения (A2, A6.5).
5. Экспорт расписания (ICS) и печатная версия для стойки.

## Проверка логики

```bash
node prototype/logic.test.mjs
```

16 сценарных проверок: подсчёт вхождений за неделю, конфликты зала и преподавателя, разовые против
еженедельных, редактирование «самого себя», границы серии (`until`), предупреждение о вместимости,
плюс две статические — уникальность `id` и отсутствие ссылок на несуществующие элементы.
Тест поднимает скрипт страницы в `vm` с DOM-заглушкой, поэтому проверяется именно код прототипа.
