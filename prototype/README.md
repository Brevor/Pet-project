# HTML-прототип ядра студии

Кликабельный прототип модуля «ядро студии» по требованиям
[doc/requirements/studio.md](../doc/requirements/studio.md): студия, персонал и роли, залы,
каталог курсов, расписание сеансов. Без сервера и базы — данные в `localStorage`.

## Запуск

```
prototype/index.html   →  открыть двойным кликом в Chrome / Edge / Safari
```

Ни сборки, ни зависимостей. Сброс демо-данных — кнопка «Сбросить демо-данные» на вкладке
«Студия» или `localStorage.removeItem('studiocrm.studio.v2'); location.reload();`.

## Экраны

| Вкладка | Что показывает |
|---|---|
| **Расписание** | Неделя 09:00–22:00, сеансы курсов по залам, фильтры по преподавателю/залу/курсу, метрики недели |
| **Курсы** | Каталог: направление, уровень, тип, длительность, вместимость, архивация |
| **Залы** | Вместимость, загрузка за неделю, архивация; занятый зал нельзя убрать |
| **Команда** | Участники с набором ролей, добавление по email, смена ролей, передача владения, деактивация |
| **Студия** | Название, часовой пояс, рабочие часы по дням, архивация, сброс демо |

## Как проверить роли

В шапке — переключатель «Вы:». Это демонстрация RBAC без бэкенда:

- **Владелец** (Анна) — полный доступ.
- **Администратор** (Мария) — всё, кроме архивации студии и управления владельцем.
- **Куратор** (Игорь) — залы, курсы, расписание, ученики; персонал недоступен.
- **Преподаватель** (Елена) — общее расписание только для просмотра.
- **Ассистент** (Олег) — то же, просмотр.
- **Ученик** (Алиса) — просмотр расписания и ничего больше.

Проверка: выбрать «Елена — Преподаватель», нажать на пустой слот — ничего не произойдёт;
кнопка «+ Сеанс» исчезнет. Переключиться на «Игорь — Куратор» — редактирование вернётся.

Несколько ролей: у Анны роли «владелец» и «преподаватель», у Марии — «администратор»
и «преподаватель». Права складываются, ограничение одной роли не отменяет право другой.

## Сценарий проверки (5 минут)

1. «Команда» → «Добавить участника» → `petr@studio.ru` (есть в демо-справочнике) → роль
   «Преподаватель» → сохранить. Участник появился.
2. Добавить `nobody@example.com` — ошибка «пользователь не зарегистрирован»: приглашений нет.
3. У нового участника открыть «Роли», добавить «Ассистент» — роли складываются.
4. «Сделать владельцем» → владелец меняется, прежний становится администратором; попытка
   деактивировать владельца — отказ.
5. «Курсы» → создать курс с названием из 141 символа — отказ; с 140 — успех.
6. «Расписание» → клик по воскресенью — отказ «студия не работает»; 21:00 + 90 минут — отказ
   по рабочим часам; два сеанса в «Зал А» в одно время — отказ с указанием конфликта.
7. «Студия» → поставить воскресенье выходным и проверить расписание.

## Проверка логики

```bash
node prototype/logic.test.mjs
```

39 проверок: разметка (уникальность `id`, все селекторы существуют), модель недели, конфликты
зала и преподавателя, рабочие часы, вместимость, RBAC и объединение ролей, добавление участника,
единственный владелец, передача владения, 140 символов, целостность сеансов.
Тест поднимает `app.js` в `vm` с DOM-заглушкой.

## Соответствие требованиям

| Требования | Где в прототипе |
|---|---|
| STU-1…STU-3, STU-6 | вкладка «Студия»: название, часовой пояс, рабочие часы, архивация |
| ACC-1…ACC-4, STF-1…STF-9 | вкладка «Команда»: добавление по email, роли, владелец, деактивация |
| ROL-1…ROL-10 | переключатель «Вы» и matrix-поведение интерфейса |
| ROM-1…ROM-6 | вкладка «Залы», запрет занятия занятого зала |
| CLS-1…CLS-6 | вкладка «Курсы», уникальность 2–140, архивация, предупреждение о вместимости |
| SCH-1…SCH-7 | вкладка «Расписание»: серии, разовые, конфликты, рабочие часы, общий просмотр |

## Ограничения прототипа

- Нет бэкенда: RBAC эмулируется переключателем участника, проверка прав не серверная (NFR-2).
- «Зарегистрированные пользователи» — демо-справочник (`directory`), а не реальные аккаунты.
- Данные живут в `localStorage` одного браузера, синхронизации нет.
- Q7 (самостоятельное присоединение ученика) не реализован — ждёт решения.
- Q3 (несколько студий у пользователя) не реализован: студия одна.
