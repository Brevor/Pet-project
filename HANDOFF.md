## 1. Что изменилось и требует архитектурного анализа

Две правки требований после первой реализации:

| Изменение | Требования | Суть |
|---|---|---|
| **Онбординг** | ACC-1, ACC-4…ACC-7 | регистрация создаёт только аккаунт; после неё — выбор «создать студию» или «присоединиться». Добавленный участник при входе сразу попадает в студию |
| **Реферальная ссылка** | ACC-8, STF-10, REF-1…REF-8 | у студии уникальный код и ссылка `/join/<код>`; владелец/администратор может менять код; старый адрес после смены отвечает 404; регистрация по ссылке даёт роль «ученик» |

**Q7 закрыт** (присоединение = реферальная ссылка). Открыты только **Q3** (несколько студий у
пользователя) и **Q8** (роль «родитель»).

## 4. Решения и факты, на которые опираться

- Стек: TypeScript, Fastify 5, PostgreSQL 18, React 18 + Vite + Tailwind, JWT, argon2 (`@node-rs/argon2`).
- Приглашений нет: аккаунт — самостоятельная регистрация или ИТ-администратор; членство оформляет
  владелец/администратор по email; для роли `student` аккаунт создаётся автоматически с временным паролем.
- Роли: `owner`, `admin`, `curator`, `teacher`, `assistant`, `student`; права — объединение ролей.
- Изоляция: `studio_id` во всех студиях-таблицах, составные внешние ключи.
- Все студийные маршруты: `/api/v1/studios/{studioId}/…`; публичные `health` и `/auth/*`.
- **Изменение схемы требует подтверждения** (proposal §10). Новое поле `studios.referral_code`
  пользователем ещё **не подтверждено** — Architect должен вынести это отдельным пунктом.

## 6. Как проверять

```bash
# тесты сервера (Node и pnpm не в PATH этой среды)
node node_modules/typescript/lib/tsc.js -p server/tsconfig.json
node server/dist/test/<suite>.test.js   # нужен DATABASE_URL
```

- `DATABASE_URL=postgres://postgres@127.0.0.1:5432/studioflow` — локальный PostgreSQL, `trust`.
- Контейнеры: `docker compose ps`; приложение на `http://localhost:8080`.
- Сборка образов: `docker compose up -d --build api web`.

## 7. Ограничения среды (важно для реализации)

- `pnpm run` не может спавнить процессы в песочнице — тесты запускаются напрямую через node.
- `vite build` локально не выполняется (esbuild не спавнится), сборка клиента — только в Docker.
- Git push из агентской среды недоступен; ветка пушится вручную.
