## 1. Назначение и границы

Модуль описывает ядро студии как рабочего пространства: создание студии, учётные записи и
персонал, роли и права, залы, каталог курсов и расписание.

Запрос пользователя: «создание студии, заведение персонала с необходимыми ролями (владелец,
администратор, куратор, преподаватель, ассистент, ученик), создание списка занятий,
создание доступных залов для тренировок, возможность создавать расписание занятий».

### 1.1. Термины

| Термин | Значение в этом документе |
|---|---|
| **Студия** | Организация-арендатор (tenant). Одна инсталляция обслуживает несколько студий |
| **Аккаунт** | Учётная запись пользователя. Существует независимо от студии |
| **Членство** | Связь аккаунта и студии. Хранит набор ролей участника в этой студии |
| **Онбординг** | Состояние аккаунта после регистрации: членства ещё нет, доступен выбор «создать студию» или «присоединиться» |
| **Сотрудник** | Участник с хотя бы одной ролью из: владелец, администратор, куратор, преподаватель, ассистент |
| **Ученик** | Участник с ролью «ученик» |
| **ИТ-администратор системы** | Служебная роль уровня инсталляции: создаёт аккаунты через API/БД, вне UI студии |
| **Зал** | Физическое помещение для тренировок (название, вместимость) |
| **Курс** | Единица каталога — то, что в запросе названо «занятием»: название, направление, уровень, тип, длительность, вместимость |
| **Сеанс** | Курс, поставленный в расписание на конкретные дату/время, зал и преподавателя |
| **Расписание** | Набор сеансов студии, отображаемый по дням и неделям |

Разделение «курс — сеанс» принципиально: правки каталога не переписывают прошлые сеансы (`Q4`).

## 3. Учётные записи и персонал

Приглашений нет: **аккаунт** создаётся самостоятельной регистрацией или ИТ-администратором системы,
а **членство в студии** оформляет владелец или администратор, указывая email существующего аккаунта.
Аккаунт глобальный и не содержит `studio_id`; `studio_id` есть у членства и у остальных сущностей модуля.

После регистрации аккаунт попадает в **онбординг** (ACC-5): создание студии — один из сценариев,
а не обязательный шаг. При регистрации роль не выбирается: владелец создаёт студию, остальные
присоединяются по реферальной ссылке (REF-5) и получают роль **«ученик»** по умолчанию.
Повышение ролей выполняет только владелец или администратор (STF-11, ACC-9).

### 3.1. Реферальная ссылка студии

Ссылка привязана к студии и служит единственным способом самостоятельного присоединения
учеников. Она **не выдаёт прав сотрудника**: роли «куратор», «преподаватель», «ассистент»
и «администратор» назначает владелец или администратор (STF-1, ROL-1).

| ID | Требование | Приоритет | Приёмка (Given → When → Then) | Источник |
|---|---|---|---|---|
| REF-1 | При создании студии автоматически создаётся уникальный код и реферальная ссылка вида `<host>/join/<код>` | Must | Given владелец создаёт студию, When студия создана, Then в ответе есть код и ссылка, ссылка открывается | ответ Q7 |
| REF-2 | Код уникален глобально (без учёта регистра), 3–32 символа из `a-z`, `0-9`, дефис, не зарезервирован | Must | Given код занят, When задаётся, Then 409 `REFERRAL_TAKEN`; при неверном формате — 422 `INVALID_REFERRAL` | ответ Q7 |
| REF-3 | Владелец и администратор могут изменить код ссылки | Must | Given владелец, When меняет код на свободный, Then новый адрес работает | ответ Q7 |
| REF-4 | После смены кода старый адрес перестаёт работать, перенаправления нет | Must | Given код заменён, When открывается старый адрес, Then 404 | ответ Q7 |
| REF-5 | Переход по ссылке показывает название студии и форму регистрации; после регистрации создаётся членство с ролью «ученик» и открывается студия | Must | Given новая ссылка, When пользователь регистрируется, Then он в студии с ролью «ученик» | ответ Q7, Q6 |
| REF-6 | Авторизованный пользователь, открывший ссылку, присоединяется без повторной регистрации; если уже участник — попадает в студию | Must | Given авторизованный аккаунт без членства, When открывает ссылку, Then членство создано; повторный переход не создаёт дубль | ответ Q7 |
| REF-7 | Ссылка не позволяет получить роль сотрудника | Must | Given регистрация по ссылке, When пользователь входит, Then у него только роль «ученик» | ROL-1 |
| REF-8 | Регистрация владельца и создание студии выполняются по общему адресу без реферального кода | Must | Given новый пользователь, When открывает адрес регистрации владельца, Then создаёт аккаунт и студию; код не требуется | замечание 2026-11-22 |

## 4. Роли и права

Набор ролей: **владелец, администратор, куратор, преподаватель, ассистент, ученик** (`Q2`).
Сотрудник может иметь несколько ролей; права складываются.

| ID | Требование | Приоритет | Приёмка (Given → When → Then) | Источник |
|---|---|---|---|---|
| ROL-1 | Роль — значение из фиксированного набора; у участника хранится набор ролей (не менее одной) | Must | Given добавляется участник без ролей, When сохраняется, Then ответ 422 | запрос |

## 12. Критерий готовности модуля (сквозной сценарий)

1. Владелец регистрируется, выбирает сценарий «владелец студии», создаёт студию и задаёт рабочие
   часы (ACC-7, REF-8); в ответе приходит реферальная ссылка.
2. Преподаватель регистрируется по реферальной ссылке студии и попадает в неё как «ученик»;
   владелец в разделе «Команда» добавляет ему роль «преподаватель» (ACC-9, STF-11).
3. Ученик открывает реферальную ссылку студии и регистрируется — получает роль «ученик» (REF-5).
4. Владелец в разделе «Команда» меняет набор ролей участника: добавляет «куратор» к «преподавателю»
   (STF-11); права складываются.
5. Владелец меняет код ссылки: новый адрес работает, старый отвечает 404 (REF-3, REF-4).
6. Преподаватель открывает расписание: кнопок создания и правки нет, вкладки «Команда», «Залы»
   и «Курсы» отсутствуют (ROL-11, ROL-12).
7. Куратор создаёт зал и затем редактирует его название и вместимость (ROM-1, ROM-7).
8. Куратор создаёт курс длительностью 120 минут и указывает преподавателя по умолчанию
   (CLS-1, CLS-5, CLS-7).
9. Куратор ставит серию по Пн и Ср: длительность сеансов — 120 минут из курса, поле недоступно
   (CLS-8, SCH-1, SCH-2).
10. Попытка изменить длительность существующего сеанса через API — 422 (SCH-10).
11. Попытка поставить два сеанса в один зал в одно время — отклонена с указанием конфликта (ROM-5).
