## 1. Назначение и границы

Достижения — награды студии, которые куратор ведёт в каталоге и выдаёт ученикам. Вместе с историей
посещений они образуют карточку успеваемости ученика. Достижения не влияют на баланс и права.

Входит: каталог достижений студии, выдача ученику, отзыв, отображение в карточке ученика,
архивация.
Не входит: автоматическая выдача по правилам, уровни/очки, публичный профиль, шеринг в соцсети.

## 3. Влияние на схему и API

- `achievements`: `studio_id`, `name`, `description`, `event_date` (nullable), `archived`,
  `created_by`, `created_at`; уникальный индекс `(studio_id, lower(name))`.
- `student_achievements`: `studio_id`, `achievement_id`, `membership_id`, `awarded_by`,
  `awarded_at`, `comment`, `revoked_at`, `revoked_by`; уникальность `(achievement_id, membership_id)`
  среди не отозванных; составные FK по `studio_id`.
- Схема БД меняется → Decision Gate, миграция — Architect.
- Права: `achievements.write` (owner, admin, curator); чтение — staff по `members.list`, ученик — свои.

## 5. Решения по открытым вопросам (2026-11-25)

Открытые вопросы закрыты ответами пользователя: лимита мест у группы нет (GRP-Q1); ученика можно зачислить без баланса (GRP-Q2); статуса «опоздал» нет (ATT-Q1); гость не отмечается сам, его отмечает администратор (ATT-Q2); отметки исправляет только администратор (ATT-Q3); отрицательный баланс запрещён (BAL-Q1); срок действия пакета нужен (BAL-Q2); внутреннее уведомление о достижении нужно (ACH-Q1); предустановленный каталог достижений нужен (ACH-Q2).
