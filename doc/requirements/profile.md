# Требования: профиль пользователя (profile)

> **Status:** draft
> **Версия:** 0.1.0
> **Дата:** 2026-11-22
> **Роль:** Analyst
> **Источники:** запрос пользователя 2026-11-22; `doc/requirements/studio.md` (ACC-1…ACC-9, ROL-*)
> **Связанные файлы:** `doc/requirements/studio.md` — аккаунты, роли и матрица прав

## 0. Назначение

Модуль описывает **вкладку «Профиль»** — личный экран любого авторизованного пользователя,
независимо от роли и студии. Профиль не управляет ролями и членствами: он показывает
собственные данные, позволяет сменить отображаемое имя и пароль.

Решение по структуре: профиль вынесен в отдельный файл, потому что аккаунт глобальный
(`users` без `studio_id`), а роли и студийные разделы — в `studio.md`. В `studio.md`
остаются только строки матрицы прав и ссылка на этот документ.

## 1. Границы

Входит: просмотр собственных данных, смена отображаемого имени, смена пароля, выход.
Не входит: управление ролями (в студии), удаление аккаунта, аватары и загрузка файлов,
смена email, 2FA, история входов, настройки уведомлений.

## 2. Требования

| ID | Требование | Приоритет | Приёмка (Given → When → Then) | Источник |
|---|---|---|---|---|
| PRF-1 | Вкладка «Профиль» доступна **всем авторизованным пользователям** любой роли (owner, admin, curator, teacher, assistant, student) и не зависит от наличия студии | Must | Given пользователь без членств (онбординг), When входит, Then вкладка «Профиль» доступна и открывается; Given ученик, Then тоже доступна | запрос 2026-11-22 |
| PRF-2 | Профиль показывает собственные данные: отображаемое имя, email, статус аккаунта; email — только для чтения | Must | Given пользователь с именем «Анна», When открывает профиль, Then видит имя и email; поля email только для чтения | запрос 2026-11-22 |
| PRF-3 | В профиле виден список членств: студии и роли пользователя в каждой из них (read-only, без управления) | Must | Given пользователь в двух студиях с разными ролями, When открывает профиль, Then обе студии и их наборы ролей показаны, изменять их из профиля нельзя | запрос 2026-11-22 |
| PRF-4 | Отображаемое имя можно изменить; пустое имя или длина > 80 символов → `422 VALIDATION` с `details.fields.displayName`; изменение сразу видно в студии и в списках участников | Must | Given профиль, When меняет имя на пустое, Then 422; When сохраняет «Анна К.», Then имя обновилось в профиле и в списках | запрос 2026-11-22, ACC-1 |
| PRF-5 | Смена пароля: текущий пароль + новый (не короче 8 символов); неверный текущий → `401 INVALID_CREDENTIALS`; новый короче 8 → `422 VALIDATION`; после смены текущая сессия остаётся рабочей | Must | Given верный текущий пароль и новый «secret1234», When сохраняет, Then пароль изменён и вход по новому паролю работает, по старому — 401 | запрос 2026-11-22, ACC-3 |
| PRF-6 | Пароль никогда не отображается и не возвращается API; в ответах профиля нет хеша и пароля | Must | Given ответ профиля, When смотрит тело, Then полей `password`/`passwordHash` нет ни в одном ответе | NFR модуля studio, ROL-4 |
| PRF-7 | «Выйти» доступна из профиля (наряду с шапкой) и очищает токен на клиенте | Must | Given профиль, When нажимает «Выйти», Then токен удалён и открыт экран входа | запрос 2026-11-22 |
| PRF-8 | Собственные роли в профиле **только для чтения**: их меняют владелец или администратор студии в «Команде» (STF-15) | Must | Given teacher, When открывает профиль, Then роли видны без чекбоксов и кнопок; изменение ролей доступно только в «Команде» | запрос 2026-11-22, ROL-6, ACC-9 |

## 3. Влияние на API и схему

- Схема БД **не меняется** (`users.display_name`, `users.email`, `users.password_hash` уже есть).
- Нужны эндпоинты: `PATCH /api/v1/me` (только `displayName`) и
  `POST /api/v1/me/password` (текущий + новый пароль). Оба — под JWT, без студийного контекста.
- `GET /me` уже возвращает пользователя и членства — используется как источник профиля.
- Коды: `422 VALIDATION` (`details.fields.displayName` / `password`), `401 INVALID_CREDENTIALS`.
- Контракты и архитектуру описывает Architect (`doc/contracts.md` §2, `doc/architecture.md` §8).

## 5. Что не входит

Аватары и загрузка файлов, 2FA, история входов, уведомления, удаление аккаунта, смена email —
до решения Q13/Q14 и отдельного подтверждения.
