# Требования: посещаемость (attendance)

> **Status:** approved
> **Версия:** 1.0.0
> **Дата:** 2026-11-25`n> **Утверждено:** 2026-11-25 пользователем (ответы на вопросы GRP-Q1…ACH-Q2)
> **Роль:** Analyst
> **Источники:** ответы пользователя 2026-11-25: преподаватель посещаемость не фиксирует; ученик отмечается сам или администратор; при посещении списывается занятие; неявка не списывает; окно самоотметки — от начала занятия до +2 часов
> **Связанные:** `doc/requirements/studio.md` (SCH-*, ROL-*), `groups.md` (ростер), `balance.md` (списание), `achievements.md` (карточка ученика)

## 1. Назначение и границы

Посещаемость фиксирует, был ли ученик на сеансе, и служит основанием для списания занятия
с баланса. **Преподаватель отметок не ставит**: отметку создаёт сам ученик (в окне сеанса) или
администратор студии (в том числе исправляет).

Входит: самоотметка ученика, отметка/исправление администратором, статусы, списание занятия по
факту посещения, история посещений для ученика и staff, аудит исправлений.
Не входит: заметки и оценки преподавателя (в этот цикл не входят), GPS/QR-подтверждение,
интеграция с турникетом, абонементы с оплатой (см. `balance.md`).

## 2. Статусы

| Статус | Кто ставит | Списание |
|---|---|---|
| `attended` — пришёл | ученик (самоотметка), администратор | **1 занятие** |
| `no_show` — не пришёл | администратор | нет |
| `cancelled` — отменил | ученик (до начала сеанса), администратор | нет |

Отменённый сеанс (`sessions.status = cancelled`) отметок не принимает.

## 3. Требования

| ID | Требование | Приоритет | Приёмка (Given → When → Then) | Источник |
|---|---|---|---|---|
| ATT-1 | Ростер сеанса — ученики групп курса сеанса (GRP-6); самоотметка — только для ученика из ростера, администратор отмечает любого ученика студии | Must | Given ученик не в группе курса, When пытается отметиться, Then 403 `NOT_IN_ROSTER` | ответ 2026-11-25 |
| ATT-2 | Самоотметка ученика доступна **с начала сеанса до +120 минут**; до начала и позже окна — 409 `CHECKIN_WINDOW_CLOSED` | Must | Given сеанс 18:00–19:30, When ученик отмечается в 18:00–20:00, Then успех; в 17:59 или 20:01 — 409 | ответ 2026-11-25 |
| ATT-3 | Самоотметка ставит `attended` и **списывает 1 занятие** с баланса ученика (атомарно с отметкой) | Must | Given баланс 5, When ученик отмечается, Then статус `attended`, баланс 4, операция списания в истории | ответ 2026-11-25, `balance.md` |
| ATT-4 | Повторная отметка того же ученика на тот же сеанс отклоняется 409 `ALREADY_MARKED`; повторный запрос идемпотентен по результату | Must | Given уже `attended`, When ученик отмечается снова, Then 409, баланс не меняется | предложение |
| ATT-5 | Ученик может отменить участие **до начала сеанса** (`cancelled`, без списания); после начала — только администратор | Must | Given сеанс в 18:00, When ученик отменяет в 17:40, Then `cancelled`; в 18:05 — 409 `CANCEL_WINDOW_CLOSED` | ответ 2026-11-25 |
| ATT-6 | Администратор ставит и исправляет любую отметку ученика своего сеанса; при смене `attended` ↔ `no_show/cancelled` баланс корректируется (списание/возврат) в той же транзакции | Must | Given `attended` и баланс 4, When админ ставит `no_show`, Then баланс 5, в истории — возврат с автором | ответ 2026-11-25 |
| ATT-7 | Преподаватель и ассистент отметок не ставят: в их UI действий нет, API → 403 | Must | Given teacher, When вызывает `POST .../attendance`, Then 403 | ответ 2026-11-25, ROL-11 |
| ATT-8 | Администратор может отметить посещение ретроспективно (за прошедший сеанс), но не раньше даты создания студии | Must | Given сеанс вчера, When админ отмечает сегодня, Then успех; до `studio.created_at` — 422 | предложение |
| ATT-9 | Ученик видит свою историю посещений: дата, курс, зал, преподаватель, статус; сортировка по дате убыванию, постранично | Must | Given 20 сеансов, When открывает «Посещения», Then видит список и статусы; чужие посещения недоступны | proposal §3 (Success 2) |
| ATT-10 | Администратор видит посещаемость сеанса (список ростера со статусами) и посещаемость ученика (история) | Must | Given сеанс, When админ открывает его, Then видит всех учеников ростера и статусы | ROL-5 |
| ATT-11 | Исправление отметки администратором фиксируется в аудите: кто, когда, было → стало, причина (необязательно) | Must | Given админ меняет `attended` на `no_show`, When открывается история, Then запись об изменении видна администратору | предложение |
| ATT-12 | Отметки на архивной студии/архивном сеансе запрещены: архивная студия — 403 `STUDIO_ARCHIVED`, отменённый сеанс — 409 `SESSION_CANCELLED` | Must | Given отменённый сеанс, When ученик отмечается, Then 409 | `architecture.md` §8 |
| ATT-13 | Время сеанса и окна считаются в часовом поясе студии | Must | Given студия UTC+3, When ученик отмечается в 19:00 МСК, Then окно рассчитано по МСК | SCH-7, NFR-3 |
| ATT-14 | API: `GET /studios/{id}/sessions/{sessionId}/attendance`, `POST .../attendance` (self/admin), `PATCH /studios/{id}/attendance/{attendanceId}`, `GET /studios/{id}/students/{membershipId}/attendance` | Must | Given права, When вызываются, Then 200/201/204; без прав — 403 | `contracts.md` (Architect) |

## 4. Влияние на схему и API

- Новая таблица `attendance`: `studio_id`, `session_id`, `membership_id`, `status`, `marked_by`
  (nullable — самоотметка), `marked_at`, `updated_by`, `updated_at`, уникальность
  `(session_id, membership_id)`; составные FK `(studio_id, session_id)` и `(studio_id, membership_id)`.
- Аудит правок: `attendance_revisions` (`attendance_id`, `from_status`, `to_status`, `reason`,
  `changed_by`, `changed_at`) либо поля в `attendance` + отдельная таблица истории.
- Схема БД меняется → Decision Gate, миграция — Architect.
- Права: самоотметка/отмена — роль `student` для себя; админ — `attendance.manage` (owner, admin).
- Списание/возврат выполняет модуль баланса (`balance.md`) в одной транзакции.

## 5. Решения по открытым вопросам (2026-11-25)

Открытые вопросы закрыты ответами пользователя: лимита мест у группы нет (GRP-Q1); ученика можно зачислить без баланса (GRP-Q2); статуса «опоздал» нет (ATT-Q1); гость не отмечается сам, его отмечает администратор (ATT-Q2); отметки исправляет только администратор (ATT-Q3); отрицательный баланс запрещён (BAL-Q1); срок действия пакета нужен (BAL-Q2); внутреннее уведомление о достижении нужно (ACH-Q1); предустановленный каталог достижений нужен (ACH-Q2).
