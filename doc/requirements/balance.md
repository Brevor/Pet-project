## 1. Назначение и границы

Баланс — целое число занятий у ученика в студии. Пополняется пакетом, который вручную начисляет
администратор; уменьшается на 1 при каждом подтверждённом посещении (ATT-3). Оплата и абонементы
в систему не входят: пакет — учётная запись остатка, деньги принимаются вне системы.

Входит: остаток, начисление пакета, списание по посещению, возврат при исправлении отметки,
история операций, просмотр учеником своего остатка.
Не входит: онлайн-оплата, скидки, срок действия пакета, заморозка, автопродление.

## 2. Требования

| ID | Требование | Приоритет | Приёмка (Given → When → Then) | Источник |
|---|---|---|---|---|
| BAL-1 | Баланс ученика — целое число занятий; хранится как сумма операций, остаток вычисляется и кешируется | Must | Given 3 начисления и 5 списаний, Then остаток = сумма операций, история полная | ответ 2026-11-25 |
| BAL-2 | Начисление пакета: администратор указывает количество (> 0, целое, до 999) и необязательный комментарий; операция фиксирует автора и время | Must | Given админ начисляет 12 занятий с комментарием «ноябрь», Then остаток +12, в истории запись с автором | ответ 2026-11-25 |
| BAL-3 | Начисление и корректировка — только владелец и администратор; куратор видит баланс, но не меняет | Must | Given куратор, When начисляет, Then 403; When открывает карточку ученика, Then видит остаток | ROL-5, ROL-7 |
| BAL-4 | Списание 1 занятия выполняется атомарно с отметкой `attended`; при ошибке списания отметка не сохраняется | Must | Given баланс 0 (отрицательный остаток запрещён), When ученик отмечается, Then 409 `NO_LESSONS_LEFT`, отметки нет | ATT-3 |
| BAL-5 | При исправлении отметки `attended → no_show/cancelled` администратором занятие возвращается операцией «возврат», исходная операция не удаляется | Must | Given списание за сеанс, When админ снимает посещение, Then остаток +1, в истории две операции | ATT-6 |

| BAL-7 | Администратор видит баланс и историю операций любого ученика студии, а также список учеников с остатком | Must | Given студия, When открывает «Балансы», Then список учеников и остатки | STF-14 |

## 3. Влияние на схему и API

- `lesson_balance_operations`: `studio_id`, `membership_id`, `kind` (`topup` | `charge` | `refund`
  | `correction`), `lessons` (знаковое целое), `comment`, `session_id` (nullable), `created_by`,
  `created_at`; уникальность операции-списания по `(session_id, membership_id)` для идемпотентности.
- Остаток — агрегат (view или кеш-колонка `students.balance` с пересчётом); решение — Architect.
- Схема БД меняется → Decision Gate, миграция — Architect.
- Права: `balance.read` (owner, admin, curator; ученик — свой), `balance.write` (owner, admin).

## 5. Решения по открытым вопросам (2026-11-25)

Открытые вопросы закрыты ответами пользователя: лимита мест у группы нет (GRP-Q1); ученика можно зачислить без баланса (GRP-Q2); статуса «опоздал» нет (ATT-Q1); гость не отмечается сам, его отмечает администратор (ATT-Q2); отметки исправляет только администратор (ATT-Q3); отрицательный баланс запрещён (BAL-Q1); срок действия пакета нужен (BAL-Q2); внутреннее уведомление о достижении нужно (ACH-Q1); предустановленный каталог достижений нужен (ACH-Q2).
